# 平台集成与后续计划

本页记录集成范围及后续方案，不代表稳定发布或平台测试已经通过。实际结果以目标
提交的测试输出和 CI 为准；未执行与准入受阻均不能算作通过。

## 平台验收

Windows/Linux 的现有功能及技能刷新保护继续保留。macOS 增加原生存储、路径、进程、
桌面权限与隔离验证入口；各平台需要分别验收。真实 vault/Keychain、用户配置、账户
额度和真实 OMH 安装不作为测试输入。数据迁移、安装、签名和发布独立评估。

## OMH 可选组件方案（尚未实施）

ATM 与 OMH 保持独立仓库、版本、CLI 和发布节奏。没有 OMH 时，ATM 自有凭据、配置和
技能管理照常可用；OMH 也可单独在终端或服务器使用。ATM 负责可选模块的展示、明确
目标、预览、确认、调用适配和结果呈现，不默认嵌入 OMH 源码/runtime，不增加无必要的
常驻 HTTP 服务。

OMH 保有状态、收据、分发、修复及事务所有权。统一盘点只统一展示，动作按明确 owner
分派：ATM 自有技能由 ATM 管理，OMH 托管资源由 OMH CLI 操作；外来或 owner 未知的
内容只读，禁止双重管理或猜测接管。

先补齐 machine 的版本化 capabilities/status/操作结果契约与 UI，区分记录态和实时健康，
表达支持操作、目标、确认、成功/失败/结果未确认和额外风险。未安装时展示不可用；
版本不兼容禁用相关操作；未知健康保持未知。执行前重验能力与目标，结束后重新读状态，
不自动重试。

第一阶段接入已有安装并在协商能力范围内提供完整可视化操作；后续另行评估显式安装/
升级引导。打开 ATM 或一次普通确认不授权安装、升级、重克隆或更改 PATH。文件替换、
清空目录、事务恢复等额外风险转终端处理，不自动代答。以上仅为计划，不扩大平台迁移
的实现范围。
