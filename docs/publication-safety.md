# 公开前的数据边界

当前源码清理不等于整个仓库可以安全公开。公开前需要分别审查所有分支/标签/PR 引用、
历史 commit、讨论文本、Actions 日志和产物；本文件不批准公开、改写历史或删除产物。

## 示例与真实状态

`TEST_ONLY/home` 下的路径、假 key、隔离配置和模拟 IPC 是测试/演示数据，不能解释为
真实用户状态。代码里的普通 Git SHA、依赖摘要、构建缓存键和签名也不是凭据。不要为
消除这些扫描误报更改运行逻辑、权限确认、只读默认或上游完整性常量。

真实密钥、用户目录、配置、安装收据、日志、截图和终端环境调查应留在 checkout 外的
私有位置。示例和公开验证记录只保留必要的合成输入、通用步骤与适用边界，不复制真实
主机、个人账户状态、工作环境或密钥库内容。构建与演示不要指向真实用户 vault/config。

## 发布前检查

- 先运行 `scripts/Audit-TrackedSource.ps1` 校验显式源码清单与凭据模式；这只是当前
  Git blob 的静态检查，不证明完整历史、图片或二进制中没有敏感信息。
- PR 只写实际运行的测试与中性限制；CI 未执行时不能写成通过，不粘贴账户或付款原文。
- 独立复核 Actions 的源码包、原始日志、可执行文件和截图。源码删除不会同步清理旧产物。
- 确认作者/提交者邮箱、第三方/工作代码的公开权利；公开与选择开源许可证分别决定。

发现真实疑似凭据时不要调用服务验证。先由所有者撤销/轮换，再协调历史、PR 引用、缓存
和产物处理；也可保留原库私有，另建仅含脱敏快照的仓库。删除最新文件或重写 PR 正文
不会清除既有副本。历史和远端产物处理需要单独批准。
