# Scope Discipline

Deliver the requested result and its necessary consequences: the smallest correct result.

Use only when the user explicitly invokes `scope-discipline` or asks to reject overengineering, scope creep, speculative hardening, redundant validation, repeated audits, or unnecessary agent work. Ordinary coding or review is not itself a trigger. An invoked workflow may reuse the reference without invoking this callable skill.

Derive the current outcome, permissions, non-goals, and required gates from the active request and owner contracts. Apply [the necessity gate](references/necessity-gate.md) before material scope or validation expansion, not every ordinary command. Do not create a second plan or ledger to restate existing boundaries.

The reference owns expansion decisions and the stop condition. Global instructions own general mutation, testing, delegation, and failure policy. This skill cannot weaken required validation, authorization, compatibility, security, or privacy contracts.

Report the result and its verification. Mention deferred or rejected work only when it changes a follow-up decision.
