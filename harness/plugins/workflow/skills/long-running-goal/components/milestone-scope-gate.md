# Milestone Scope Gate

At milestone entry, read its scope, non-goals, permissions, later-stage ownership, and declared gates from the goal. Planned work needs no extra scope ceremony or duplicate fields.

Before material scope or validation expansion, apply [the shared necessity gate](../../scope-discipline/references/necessity-gate.md): execute current work and evidenced necessary consequences within authorization; leave later milestone work with its owner; reject speculation; resolve semantic conflicts in the active goal before affected mutation. Reusable skill changes require their own existing authorization.

Record only material scope changes and their evidence in the goal. A change to behavior, ownership, persisted state, dependencies, milestone order, or validation surface is material; ordinary commands and caller updates implied by the gate are not.

The checkpoint component has already recorded its evidence before the milestone-scope exit gate passes. Advance when scope and necessary consequences are complete, required validation and review pass, and no in-scope failure or semantic conflict remains. Continue without another final scope audit.
