---
name: grilling
description: Stress-test a plan, decision or idea through focused questions. Use when the user asks for grilling, an interview or a challenge to their assumptions.
---

Stress-test the user's plan, decision or idea through a **design tree**: decisions and the questions that depend on them. Start with already confirmed decisions and the intended scope.

Work in manageable rounds. The **frontier** contains consequential questions whose prerequisites are settled. Ask the most useful independent questions together, with concise options and a recommendation when justified; wait for answers before resolving dependent decisions. Use the environment's question interface when available.

Look up facts from the repository or available sources yourself. Delegate bounded fact-finding only when useful and authorized. While evidence is pending, continue with independent questions rather than asking the user to reconstruct information you can inspect.

Recompute the frontier as answers arrive. Reuse settled answers and distinguish assumptions from confirmed decisions. Finish when the decisions needed for the requested outcome are clear and material uncertainties are resolved or explicitly left open; exploring every hypothetical branch is unnecessary.

A request to discuss remains a discussion. When implementation is already authorized, continue within that scope once the required decisions are settled; do not add a second blanket confirmation. When recording persistent domain knowledge is part of the requested work, load `domain-modeling` through the active harness's supported skill-loading mechanism before applying it. If unavailable, report the missing dependency and blocked documentation step; discussion can continue within its existing scope.
